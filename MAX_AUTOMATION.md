# MAX: публикации без удаления существующих материалов

Бот: **ПроОкна24 | Помощник**. Канал: https://max.ru/channel_ProOkna24

Автоматизация предназначена только для **ручной проверки подключения и публикации согласованных текстовых постов**. Она никогда не удаляет, не редактирует и не закрепляет старые сообщения, не меняет настройки канала и не управляет подписчиками. Расписание отсутствует.

## Предварительные условия

В репозитории GitHub Actions → Secrets and variables → Actions:
- `MAX_BOT_TOKEN` — уже создан пользователем (не вставлять в файлы, чат или скриншоты).
- `MAX_CHANNEL_ID` — числовой идентификатор существующего канала. Он **не равен** ссылке канала или нику бота. Получается из событий `bot_added`/`bot_admin_permissions_changed` через API MAX; не угадывать.

Запустить на GitHub → Actions → `MAX — проверка и публикация после согласования` → Run workflow:
- Режим `check`: GET /me; если есть `MAX_CHANNEL_ID` — проверить членство бота; если ещё нет — один раз прочитать последние события без публикации и вывести только возможные числовые ID каналов. MAX API не поддерживает список всех каналов бота. Если событие отсутствует, для получения ID нужна настройка получения событий либо повторное событие; не удалять бота ради генерации события.
- Режим `publish`: требуется `MAX_CHANNEL_ID`, согласованный пост и точное подтверждение `ПУБЛИКОВАТЬ`. Без них будет ошибка и ничего не публикуется.

API: https://platform-api2.max.ru; токен только в HTTP заголовке Authorization (не в URL и не в логах).

**Важно:** создание файлов GitHub Actions не запускает рабочий процесс автоматически. Отправка поста возможна только после отдельного явного подтверждения. Все другие сервисы сайта продолжают работать без изменений.

## Сертификат MAX API

MAX с 19 июля 2026 года использует сертификат российского доверенного центра. На GitHub Actions по умолчанию этого корневого сертификата нет, что вызывает ошибку `CERTIFICATE_VERIFY_FAILED` даже при корректном токене. Для HTTPS-запросов MAX используется файл `scripts/certs/russian_trusted_ca.pem` (сертификаты Минцифры), взятый из открытого проекта [Fgeeha/max-action](https://github.com/Fgeeha/max-action/blob/Master/internal/maxapi/certs/russian_trusted_ca.pem), который ссылается на [официальный источник](https://gu-st.ru/content/Other/doc/russiantrustedca.pem). Проверка TLS **не отключается**, системные доверенные сертификаты runner не изменяются. Сертификаты могут потребовать обновления до марта 2027 года.
